# Урок 02. Индексы: композитный индекс и keyset-пагинация

## Условие задачи

Есть интернет-магазин. DDL и тестовые данные — в `schema.sql` (таблицы `customers`, `orders`, `order_items`, 50 000 заказов и 125 000 позиций).

Нужно реализовать первую страницу ленты «дорогих» заказов для операционного дашборда:

- регион `EU`;
- статус `new` или `paid`;
- создан в октябре 2026 (`2026-10-01 00:00:00+00` включительно, `2026-11-01 00:00:00+00` не включая);
- курсор пользователя: последний показанный заказ имел `(total_amount, order_id) = (500.00, 30000)`; нужны строки, идущие **строго после** курсора в порядке сортировки;
- сортировка: `total_amount` по убыванию, при равенстве — `order_id` по убыванию;
- размер страницы — 20 строк.

Вернуть колонки `order_id`, `created_at`, `total_amount`.

## Что сдать

В `solution.sql` — две части:

1. Итоговый `SELECT` (один запрос), дающий ожидаемый результат.
2. `CREATE INDEX`-ы, которые ты считаешь нужными для этого запроса.

Дополнительно пришли текстом `EXPLAIN (ANALYZE, BUFFERS)` для этого запроса **до** создания индексов и **после** — и коротко объясни, что изменилось.

## Ограничения

- Пагинация только keyset (через условие на курсор). `OFFSET` запрещён.
- Нельзя менять данные и схему таблиц; можно только создавать индексы.
- Нельзя отключать планировщик (`enable_seqscan = off` и подобное) — план должен выбираться естественно.
- Решение должно быть одним `SELECT` (CTE и подзапросы разрешены).
