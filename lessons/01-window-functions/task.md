# Урок 01. Оконные функции: дневная активность по счёту

## Условие задачи

Есть таблицы `accounts` и `transactions` (DDL и тестовые данные — в `schema.sql`).

Проведённой считается транзакция со `status = 'posted'` (транзакции `declined` в расчётах не участвуют). У `amount` положительное значение означает пополнение, отрицательное — списание.

Для каждого счёта и каждого календарного дня, в который по нему была **хотя бы одна проведённая транзакция**, нужно вывести одну строку со следующими колонками:

1. `account_id` — идентификатор счёта.
2. `tx_dt` — день активности.
3. `day_net` — чистое изменение баланса за этот день (сумма `amount` проведённых транзакций дня).
4. `running_balance` — накопленное изменение баланса с первого дня активности счёта по этот день **включительно**.
5. `prev_day_net` — значение `day_net` предыдущего дня активности счёта (`NULL`, если предыдущего дня нет).
6. `day_dense_rank` — плотный ранг дня по `day_net` внутри счёта по убыванию: дни с одинаковым `day_net` получают одинаковый ранг, пропусков в нумерации быть не должно.
7. `is_best_day` — `true`, если это лучший день счёта, иначе `false`. Лучший день — день с максимальным `day_net`; при равенстве лучшим считается **более ранняя дата**. У каждого счёта должен быть ровно один лучший день.

Сортировка результата: `account_id` по возрастанию, затем `tx_dt` по возрастанию.

## Ограничения

- Обязательно используй оконные функции.
- Запрещены самосоединения таблицы `transactions` (`transactions t1 JOIN transactions t2`).
- Запрещены коррелированные подзапросы.
- Запрещены временные таблицы и `CREATE TABLE ... AS`.
- Разрешены `CTE` (`WITH`), `GROUP BY`, `HAVING`.
- Решение должно быть одним SQL-запросом.
