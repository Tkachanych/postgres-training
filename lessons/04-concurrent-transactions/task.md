# Урок 04. Конкурентные транзакции: MVCC, write skew и блокировки

## Условие задачи

В ночной смене два дежурных: Анна (101) и Борис (102). Каждый может снять с дежурства только себя, если после этого в смене останется хотя бы один дежурный. Оба могут отправить запрос одновременно. Строка в `shifts` представляет смену, а `shift_staff` хранит состояние её участников.

Нужно воспроизвести нарушение правила и проверить два способа его защиты. Основной эксперимент проводится на смене 1. Остальные смены содержат тех же сотрудников, поэтому изменение должно учитывать и смену, и сотрудника.


```sql
SELECT staff_id, on_call
FROM shift_staff
WHERE shift_id = 1
ORDER BY staff_id;
```

## Практика

1. **Снимки.** В A начни `READ COMMITTED` и прочитай число дежурных. В B отдельной транзакцией сними Анну с дежурства и зафиксируй изменение. В A повтори тот же запрос. Восстанови данные и повтори с `REPEATABLE READ` в A.
2. **Write skew.** В обеих сессиях начни транзакции `REPEATABLE READ`. Сначала обе должны увидеть двух дежурных. Затем A снимает Анну, B снимает Бориса, и обе пытаются зафиксировать изменение. Восстанови данные и повтори тот же порядок с `SERIALIZABLE` в обеих сессиях. Запиши, на какой команде произошёл отказ и какой SQLSTATE показал DBeaver. Повтори неудавшуюся операцию целиком в новой транзакции и зафиксируй, какое решение она теперь принимает.
3. **Явная блокировка.** На `READ COMMITTED` реализуй операцию снятия с дежурства через блокировку строки соответствующей смены. Доведи A до момента, когда изменение сделано, но ещё не зафиксировано. Запусти операцию в B. Пока B ждёт, проверь из A, кто её блокирует, через `pg_blocking_pids(<PID B>)`. Зафиксируй A и дай B завершить операцию.

## Ожидаемые результаты

| Прогон | Что должно получиться |
|---|---|
| Снимки, `READ COMMITTED` | A видит сначала 2, потом 1 |
| Снимки, `REPEATABLE READ` | A видит 2 в обоих запросах |
| Write skew, `REPEATABLE READ` | Обе транзакции фиксируются, дежурных 0 |
| Write skew, `SERIALIZABLE` | Одна из транзакций получает `40001`; дежурный остаётся один и после повтора |
| Блокировка, `READ COMMITTED` | B ждёт A; после фиксации A операция B оставляет Бориса на дежурстве |

Для `SERIALIZABLE` фиксируй наблюдение: стадия отказа зависит от порядка команд.

## Ограничения

- Операция может менять только строку выбранного сотрудника в выбранной смене.
- В варианте с явной блокировкой все операции снятия с дежурства должны следовать одному протоколу. Используй блокировку строки смены.
- В ходе экспериментов сохраняй схему и исходный набор строк.
